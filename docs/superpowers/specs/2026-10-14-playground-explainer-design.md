# Concept playground: animated HTML explainers (Design)

Date: 2026-10-14
Status: approved (approach B — two-step brief → scaffold-composed artifact; `/playground` surface;
sandboxed iframe with scripts)
Scope: a `/playground` page where a user gets an animated, self-contained HTML explainer for any
concept. Entry from the results review card prefills the concept context. Generation is two model
calls inside one request (brief → artifact), the server composes the final document from a
server-owned scaffold, validation is a quality gate, and the artifact executes only inside a
locked-down `srcdoc` iframe. Cross-user cache mirrors `question_explanations`. No change to the
markdown explanation pipeline, no schema change to existing tables, no share links, no nav entry.

## 1. Objective

Explanations today are a single markdown string (`explanationSchema`,
`src/lib/server/quizSchema.js`), generated by `/api/explain`, cached in `question_explanations`,
and rendered through the sanitized unified pipeline (`src/lib/client/markdownRenderer.js`) — raw
HTML from the model is deliberately stripped, and AGENTS.md codifies that. Rich static visuals
already have two outlets (KaTeX math, lazy Mermaid diagrams); what has no outlet is **animation
and interactivity**.

The research question "can HTML be included in question explanations?" resolves as: **no** — raw
model HTML must never enter the app DOM. The safe equivalent is an isolated surface where
generated HTML/CSS/JS runs in an opaque origin iframe, never in the app document. That surface is
this feature.

Success criteria:

- From a results review card, one tap opens `/playground` with topic/question/answer prefilled;
  generation produces a working animated artifact within the 90 s deadline.
- Repeating the same request (same topic + context + language) is an instant cache hit with no
  model call; cache hits are served before the rate limiter, as `/api/explain` does.
- The artifact renders only inside `sandbox="allow-scripts"` (no `allow-same-origin`) with a
  `default-src 'none'` CSP; a DB-seeded artifact that tries `parent.document`, `fetch`, and
  `localStorage` provably reaches none of them (E2E, §9).
- `npm run eval:artifact` reports per-concept validity, console errors, animation activity, byte
  sizes, and screenshots, and its report is the evidence that picks `ARTIFACT_MODEL` (§9).

## 2. Non-goals

- **HTML in explanations.** The markdown pipeline (`MarkdownContent.svelte`,
  `markdownRenderer.js`, `rehype-sanitize` schema) is untouched.
- **Public share links** for artifacts (view-only URLs, slugs, SEO/noindex decisions).
- **Concept suggestions** from weak answers on the playground page.
- **Regenerate / variant browsing.** One artifact per concept+language; retry only after failure.
- **Navigation changes.** No TopNav/BottomNav entry in v1; entry points are the review card and
  the direct URL. Discoverability is evaluated from telemetry before adding more entries.
- **In-generation headless render verification.** Rendering checks live in the dev-time eval
  script, not in the request path.
- **Streaming/progress stages from the server.** The client shows honest coarse states; no
  fake precision.

## 3. Decisions

**D1 — Two-step pipeline in one request: brief → artifact.** A cheap structured call produces a
concept brief (framing, level, animation recipe picks, section plan); a second call writes only
the artifact body against the scaffold (§5). One shared 90 s deadline with the explain route's
retry discipline. Rejected: single-call generation (a lite model writing a working animated
document in one shot is the riskiest assumption in the feature; the brief also feeds UI metadata
and the cache).

**D2 — Models are constants settled by evidence.** Brief model:
`gemini-flash-lite-latest` (repo default). `ARTIFACT_MODEL` is a config constant whose value is
chosen by the `eval:artifact` report — candidates are the lite model and a stronger Flash alias —
ships whichever passes the quality gate at acceptable cost, and is revisited only with new
evidence. `ARTIFACT_BRIEF_MODEL` and `ARTIFACT_MODEL` both live in `src/lib/server/quizConfig.js`.

**D3 — Fragment-only output; the server owns the document.** The model returns `{ html, css, js }`
as separate fields. The scaffold (server module) owns doctype, `<html lang>`, theme attribute,
CSP meta, base CSS, title/summary rendering, the height-report script, and the IIFE wrapper
around model JS. Rejected: model-authored full documents — head/CSP/theme must never be
model-controlled, and a fixed shell removes a whole class of layout failures.

**D4 — The sandbox is the security boundary; validation is a quality gate.** Static validation
runs before anything is stored or served, but denylist scans are regex-level and will have gaps.
Safety rests on iframe isolation + CSP (§6), both browser-enforced. Rejected: sanitizing generated
HTML into the app DOM — exactly what AGENTS.md forbids.

**D5 — Storage mirrors `question_explanations`; compose at serve time.** New `concept_explainers`
table stores the fragment payload + brief metadata under a hashed cache key. The response document
is composed per request so the requesting client's `theme` is honored without entering the cache
key. Rows are append/update only — never deleted (archive-first rule).

**D6 — Stricter rate limit than explanations.** Artifact generation is the most expensive call in
the app: `limit: 5` per minute per client (explain uses the 10/min default), bucket
`/api/playground`. Cache hits do not consume quota.

**D7 — No regenerate in v1.** Cache-first means repeats are instant and consistent across users.
A failed generation surfaces an error with Retry; a *dissatisfying but valid* artifact has no
button until telemetry shows demand.

**D8 — Height sync via a scaffold-owned script.** The artifact reports its content height with
`ResizeObserver` → `parent.postMessage({ type: 'selftest-explainer-height', height }, '*')`. The
parent accepts only messages whose `event.source === iframe.contentWindow` and `type` matches,
clamps to [320 px, 85 vh], and falls back to a fixed height if no message arrives. Model code is
never involved in sizing.

## 4. API contract

`POST /api/playground`

```json
{
  "topic": "Newton's third law",
  "question": "optional — review context question text",
  "answer": "optional — review context correct answer",
  "language": "english",
  "theme": "light"
}
```

- `topic` required (≤ `MAX_TOPIC_LENGTH` 500), `question` optional
  (≤ `MAX_QUESTION_TEXT_LENGTH` 2000), `answer` optional (≤ `MAX_ANSWER_TEXT_LENGTH` 1000);
  reuse `parseRequestBody` and the explain route's length checks.
- `language` ∈ `VALID_LANGUAGES`, default `english`. `theme` ∈ `light|dark`, default `light`,
  cosmetic only — **not** part of the cache key.

Response `200`:

```json
{
  "title": "Newton's third law, in motion",
  "summary": "Every push comes with an equal and opposite push.",
  "recipes": ["step-reveal", "toggle-compare"],
  "html": "<!doctype html>… composed document …",
  "cached": false
}
```

- `html` is the composed document, ≤ `MAX_ARTIFACT_DOCUMENT_BYTES` (150 KB). The client assigns
  it to `iframe srcdoc`; nothing else is done with it.
- Cache-first ordering exactly like `/api/explain`: read cache → touch (`use_count`,
  `last_used_at`) → `logApiEvent` → return, all **before** the rate limiter. Misses take the
  rate-limit quota, then generate.
- Server log: `logApiEvent({ route: '/api/playground', action: 'generate_explainer', metadata:
  { topic, language, cached, briefModel, artifactModel, durationMs, generationFailure? } })`.
  `generationFailure` carries `{ stage: 'brief' | 'artifact' | 'validation', issues: [...] }` —
  the same shape existing generation-failure telemetry uses.

Errors (mirroring `/api/explain` conventions):

| Status | Code | When |
| --- | --- | --- |
| 400 | `PLAYGROUND_FIELDS_REQUIRED` | `topic` missing |
| 400 | `PLAYGROUND_FIELDS_TOO_LONG` | any field over its cap |
| 400 | `INVALID_LANGUAGE` | unknown language value |
| 413 | `REQUEST_TOO_LARGE` | body over `MAX_REQUEST_BODY_BYTES` |
| 429 | `API_LIMIT_ERROR_CODE` | over quota; `X-RateLimit-*` headers as explain |
| timeout | `API_TIMEOUT_ERROR_CODE` | 90 s deadline exceeded (`classifyApiError`) |
| 500 | `ARTIFACT_INVALID` | validation failed and the repair attempt failed too |
| 500 | `EXPLAINER_FAILED` | fallback via `classifyApiError` |

## 5. Generation pipeline

### 5.1 Brief

`generateConceptBriefPrompt({ topic, question, answer, language })` in
`src/lib/server/prompt.js`; response validated by `conceptBriefSchema` added to
`src/lib/server/quizSchema.js`:

```js
{
  concept: string,        // specific concept, e.g. "Newton's third law"
  title: string,          // user-visible artifact title
  summary: string,        // one line
  level: string,          // inferred level, e.g. "class 10"
  recipes: array(RECIPE_IDS),                 // from the scaffold's recipe menu
  sections: array({ heading, purpose, recipe }).min(2).max(5)
}
```

- Output cap `MAX_ARTIFACT_BRIEF_OUTPUT_TOKENS` (1024). One retry on transient provider errors.
- `RECIPE_IDS` exports a starter menu from `src/lib/server/artifactScaffold.js` (final set in
  implementation; ~6): `step-reveal`, `timeline`, `particle-flow`, `orbit`, `graph-plot`,
  `toggle-compare`. Each recipe has an id, a one-line description (prompt), and optional
  scaffold helper classes/utilities.

### 5.2 Artifact

`generateArtifactPrompt({ brief, language, contract, repairIssues? })`; response validated by
`artifactPayloadSchema` (`{ html: string, css: string, js: string }`).

- Output cap `MAX_ARTIFACT_OUTPUT_TOKENS` (8192, the same envelope as a 25-question batch).
- Attempts (all inside the shared 90 s deadline): 1 retry on transient/JSON-parse failure, then —
  if the payload parses but fails validation — 1 repair call whose prompt includes the validator's
  `issues` list. If that fails, `ARTIFACT_INVALID`. No further recursion.
- The prompt states the contract explicitly: self-contained (no network), CSS/SVG/vanilla JS
  only, no external assets, transform/opacity animations preferred, respect
  `prefers-reduced-motion` (scaffold helper provided), visible controls labeled, and the byte
  budgets.

### 5.3 Scaffold

`src/lib/server/artifactScaffold.js` exports:

- `ARTIFACT_SCAFFOLD_VERSION` (bumped when the template changes; part of the cache key),
- `ARTIFACT_RECIPES` / `RECIPE_IDS`,
- `composeArtifactDocument({ brief, payload, language, theme })` → full document:
  - `<!doctype html>`, `<html lang="en|hi" data-theme="light|dark">`, charset + viewport;
  - CSP meta (§6);
  - base CSS: system font stack (no webfonts), spacing scale, both palettes mirroring
    `src/lib/styles/globals.css` tokens, stage primitives, reduced-motion helpers, and
    `overflow-y: auto` so a clamped iframe scrolls internally;
  - title + summary rendered server-side (HTML-escaped) so the model never repeats them;
  - body slot = model `html`; single `<style>` slot = base CSS + model `css`; script slot 1 =
    scaffold height-report script; script slot 2 = model `js` wrapped in
    `'use strict'` IIFE.

### 5.4 Validation

`src/lib/server/artifactValidation.js` — pure function
`validateArtifactPayload(payload, { limits })` → `{ ok, issues: [{ code, detail }] }`. Written
test-first from this failure list (§9):

1. Size: `html` ≤ 96 KB, `css` ≤ 32 KB, `js` ≤ 24 KB, composed document ≤ 150 KB.
2. Structure (parse5 over `html`): banned tags — `script`, `style`, `link`, `meta`, `iframe`,
   `object`, `embed`, `base`, `form`, `video`, `audio`, `source`, `track`, `template`; `svg`,
   `canvas`, `img`, `input`, `button`, `label`, `details` are allowed.
3. Attributes: no `on*` handlers, no `style` attributes (CSS lives in the `css` field), `href`
   only same-document (`#…`) or absent, `src` only `data:`.
4. CSS: no `@import`, no `expression(`, `url()` only `data:`.
5. JS token denylist (defense in depth): `fetch(`, `XMLHttpRequest`, `WebSocket`, `EventSource`,
   `sendBeacon`, `eval(`, `new Function`, dynamic `import(`, `document.cookie`, `localStorage`,
   `sessionStorage`, `indexedDB`, `window.open`, `location.assign`, member access on
   `window.parent`/`parent`/`window.top`/`top` (`\b(parent|top)\b\s*\.` regex, which also catches
   the `parent.` inside `window.parent.`), and
   `</script` (case-insensitive; the composer must never be broken out of).
6. External URLs: `https?://` rejected in any attribute value or `url()`; allowed in visible text.

A payload that fails validation is never stored and never served, regardless of repair outcome.

### 5.5 Cache

`src/lib/server/explainerCache.js` mirrors `explanationCache.js` exactly:
`buildExplainerCacheKey`, `getCachedExplainer`, `saveExplainer` (`ON CONFLICT DO NOTHING`),
`touchExplainer` (`use_count + 1`, `last_used_at = NOW()`), plus the key version constant.

Key formula (pinned in E2E by independent computation):

```
sha256(JSON.stringify([
  'pg-v1',                        // ARTIFACT_CACHE_KEY_VERSION
  ARTIFACT_PROMPT_VERSION,        // bump when prompt semantics change
  ARTIFACT_SCAFFOLD_VERSION,      // bump when the template changes
  normalize(language).toLowerCase() || 'english',
  normalize(topic),
  normalize(question ?? ''),
  normalize(answer ?? '')
]))
```

`normalize` is the explanation cache's NFC/trim/whitespace-collapse helper, case preserved.

Table `concept_explainers` mirrors `question_explanations`: `id BIGSERIAL PRIMARY KEY`,
`cache_key TEXT NOT NULL UNIQUE`, `language TEXT NOT NULL DEFAULT 'english'`, `concept TEXT`,
`payload JSONB NOT NULL`, `model TEXT`, `created_at`, `last_used_at`, `use_count`, plus the
`last_used_at DESC` index. `payload` is the fragment — `{ title, summary, recipes, html, css,
js }` — not the composed document, and `concept` is the brief's concept string for auditing.
Composing at serve time keeps `theme` out of the key (D5).

## 6. Security model

- **Iframe**: `srcdoc` + `sandbox="allow-scripts"` and nothing else — no `allow-same-origin`,
  so the artifact runs in an opaque origin: no cookies, storage, or same-origin reach into the
  app; no forms, popups, modals, top-navigation, or downloads. `referrerpolicy="no-referrer"`;
  meaningful `title` attribute.
- **CSP, composed into every document** (never model-controlled): `default-src 'none';
  style-src 'unsafe-inline'; script-src 'unsafe-inline'; img-src data:; font-src 'none';
  connect-src 'none'; base-uri 'none'`. Even if validation misses something, the artifact cannot
  reach the network or a base URL.
- **Threat model**: `topic`/`question`/`answer` are attacker-controlled prompt inputs; the model
  output is therefore untrusted content, treated exactly like any other model output — it is
  never interpolated into the app DOM, only into an attributed `srcdoc` string and eventually
  into the sandbox. Prompt-injection resistance is not assumed from the model; it is enforced at
  the browser boundary.
- **Validation is not the boundary** (D4); the E2E sandbox-boundary test (§9) proves the
  boundary against a DB-seeded document that validation would have rejected.
- **Serving is read-only**: rows never update except `use_count`/`last_used_at`; nothing is
  deleted from the table.

## 7. Client

**Page** `src/routes/playground/+page.svelte` (+ `src/routes/playground/+page.js` with
`export const prerender = true`, and the `/hi/playground` twin following the `/hi/practice`
pattern). Public page pattern applies: shell prerendered, all generation client-side, page listed
in `buildSitemap()` with the automatic en/hi alternates.

- **Before generation**: heading + one-line description, topic input, curated example chips
  (en+hi), and — when arrived via deep link — a collapsed "from your question" context chip.
  Deep links **prefill but never auto-generate** (cost and surprise control).
- **During generation**: existing shimmer/thinking-dots pattern with coarse honest copy
  ("Planning…" → "Drawing…"), no fake precision.
- **Result**: card with brief `title` + `summary`, then `ArtifactFrame` (below). Actions:
  "New concept" resets to the input state; on failure, an error card with Retry (re-request).
- **Requests** carry `language` (current app language) and `theme` (current `data-bs-theme`).

**Component** `src/lib/client/ArtifactFrame.svelte`: renders the iframe with the exact sandbox
attributes from §6, assigns `srcdoc`, wires the height-sync listener (D8: source-checked,
clamped, rAF-debounced) with a fixed-height fallback, and unmounts the iframe on navigation.

**Review integration** (`src/lib/client/ResultReviewItem.svelte`): a second action beside
"Generate explanation" — `Explain visually` — linking to
`buildPlaygroundHref({ topic, question, answer })`. Helper in
`src/lib/shared/playgroundLink.js` (pure, tested): `URLSearchParams`-based, truncates `question`
to 400 chars and `answer` to 200 chars, encodes everything. The link carries no state; the
playground page treats params as prefill only. Clicking emits `playground:entry-from-review`.

**URL contract**: `/playground?topic=…&question=…&answer=…` (all optional; `topic` alone is
valid). Language and theme are never URL params — they follow the session.

**Starter locale keys** (final wording during implementation, both files, per AGENTS.md):
`playgroundTitle`, `playgroundIntro`, `playgroundTopicLabel`, `playgroundTopicPlaceholder`,
`playgroundExamplesLabel`, `playgroundGenerate`, `playgroundPlanning`, `playgroundDrawing`,
`playgroundFromYourQuestion`, `playgroundNewConcept`, `playgroundErrorIntro`,
`playgroundRetry`, `explainVisually`.

**Unit (vitest, test-first — AGENTS.md's isolated-system rule):**

- `src/lib/server/artifactValidation.test.js` — written from §5.4's failure list before the
  validator exists: every banned tag, `on*` attribute, `style` attribute, `href`/`src` shape,
  `url()` shape, oversize case, JS denylist token, and the `</script` escape attempt.
- `src/lib/server/artifactScaffold.test.js` — composition is deterministic; CSP meta, `lang`,
  `data-theme`, escaped title/summary, height script, and IIFE wrap are always present; model
  fields cannot introduce a second `<html>`/`<head>` or break out of the script slot.
- `src/lib/server/explainerCache.test.js` — key normalization and version tuple, mirroring
  `explanationCache.test.js`.
- `src/lib/shared/playgroundLink.test.js` — truncation, encoding, optional fields.

**E2E** `tests/e2e/playground.e2e.js` (artifact via `artifactReporter.js`):

1. **Seeded-cache, model-free** (blueprint `explanation-cache.e2e.js`): compute the §5.5 key
   independently in the test (hardcoded `'pg-v1'` + version literals pins the formula), seed a
   row through the testDb bridge, POST twice, assert `cached: true` both times, served `html`
   contains the seeded marker, starts with `<!doctype html>`, carries the CSP meta and the
   requested `data-theme`, and `use_count` delta is 2. Evidence attached.
2. **UI flow** with a stubbed `/api/playground` (`page.route`): prefill from a deep link, loading
   states, artifact card renders, iframe `sandbox` attribute is exactly `allow-scripts`, `title`
   is set, error + Retry path on a stubbed 500, "New concept" resets. Review-card link builds the
   documented href (existing stubbed-paper patterns).
3. **Sandbox boundary** (the point of the feature): seed a fragment whose JS tries
   `parent.document.documentElement.setAttribute('data-pwned','1')`, `fetch('/api/explain')`, and
   `localStorage.setItem('pwned','1')`; open the playground with the matching key; assert the
   parent DOM never gains `data-pwned`, no request is logged by `page.on('request')` after the
   document loads, and parent `localStorage` is untouched. This row bypasses validation on
   purpose — it proves the browser boundary, not the validator.

**Eval** `npm run eval:artifact` (`scripts/evalArtifact.mjs` + a fixtures file): ~8 concepts
across physics/chemistry/biology/math — 6 English + 2 Hindi. It imports the pipeline functions
directly, generates each artifact, then loads each composed document in Playwright Chromium
asserting — zero console errors/page errors, zero network requests, measurable DOM mutation
activity (animation actually runs), byte sizes within budget — and writes
`test-results/artifact-eval.json` plus screenshots. The report is the decision gate for
`ARTIFACT_MODEL`, token caps, and recipe guidance; screenshots are human-reviewed once.

**Gates**: `npm run lint`, `npm run check`, `npm run test`, `npm run test:e2e` (artifact stamped
with SHA; existing explanation-cache and security-hardening specs green unmodified),
`npm run verify:vercel` (new route + sitemap entries), one `telemetry:report --days=30` read after
staging.

## 11. Known limitations

- The validator is parse/regex-level; the sandbox and CSP are the boundary (D4) — stated and
  tested, not assumed.
- Height messages cannot be origin-verified (opaque origin); a malicious artifact can only
  misreport its own iframe height, which is clamped.
- Artifact quality varies by concept and language; there is no regenerate affordance in v1 by
  design (D7).
- Generation is a synchronous request with a 90 s worst case; no streaming. Slow-path latency is
  accepted for v1 and measured via `durationMs` telemetry.
- Cache rows accumulate (append-only, like `question_explanations`); retention tooling is the
  existing archive-first policy, not a new mechanism.
- Scaffold palettes mirror `globals.css` by hand; drift is caught by eval screenshots, not
  automated pixel tests.
